Next targets after v12 Leibniz + presented contexts: SOUNDNESS and COMPLETENESS, completeness the priority ("easiest way to spot if something is wrong with the design, and the ultimate prize"). First: a v12 interpreter. Decided to port the `DiaIdxSem.lean` extent/content design (possible object = extent (set of accessible worlds) + ONE object at each), NOT update RModelB/TermInterp/InterpMeta/CanonicalModel (v9 syntax, image-set posEval) — those stay as reference.

**User decisions (2026-09-12):**
- (A) SUBOBJECT style: each domain is a carrier type with an INJECTIVE map into extent/content objects (not an admissibility predicate on objects). Reasons: distinct objects at some level of abstraction may be interpreted as the same; heads off objections about non-existent (non-admissible) objects.
- (B) Closure = "the FUNCTION ALGEBRA LIFTS to each domain" (as in old design; algebra generalised for products, GFunc). NOT a Henkin-style "every term denotes" condition.
- (C) POINTED models (actual world), mainly for a philosophical audience.

**Design as built (QML_v12_Model.lean):** `Frame` (W, actual, R, D base domains, carriers Nec A w / Pos A w, funcInterp, relInterp); `Frame.Dom` by recursion on VarType (Var ↦ D, 𝟙 ↦ PUnit, × ↦ × DEFINITIONAL, □A ↦ Nec A, ◇A ↦ Pos A); `necEval : Nec A w → ∀ w' : Acc w, Dom A w'` and `posEval : Pos A w → Σ E : Set (Acc w), ∀ w' ∈ E, Dom A w'` both injective; `GFunc` algebra (id/comp/fst/snd/pair/unit/func with argument family/boxMap/boxPair/boxUnit/diaMap/strength) evaluated through `Ops` (necMap/necPair/necUnit/posMap/posStrength); laws necMap_eval, necPair_eval, posMap_eval (same extent, mapped content), posStrength_eval. No Stk machinery (modal lifts are GFunc constructors).
